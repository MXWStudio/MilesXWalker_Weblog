# 📐 简历生成器架构重构说明

## 🎯 重构目标

将单一大型组件拆分为多个小型、职责单一的模块化组件，提高代码可维护性和可扩展性。

## 🔄 重构前后对比

### 重构前

```
src/
├── pages/
│   └── ResumeGenerator.vue          # 单一大组件（900+ 行）
├── components/
│   └── resume/
│       ├── RichTextEditor.vue
│       └── README.md
├── stores/
│   └── resume.js                    # Store
└── utils/
    └── pdfExport.js                 # PDF 工具
```

**问题**:

- ❌ 单一组件过大，难以维护
- ❌ 编辑区和预览区耦合在一起
- ❌ 缺少岗位选择功能
- ❌ 文件命名不统一

### 重构后

```
src/
├── components/
│   ├── ResumeGenerator.vue          # 主组件（整合）
│   ├── ResumeEditor.vue             # 可编辑区
│   ├── ResumePreview.vue            # PDF 预览区
│   ├── JobSelector.vue              # 岗位选择器
│   └── resume/
│       ├── RichTextEditor.vue
│       └── README.md
├── utils/
│   ├── blogParser.js                # 博客数据抓取
│   └── pdfExporter.js               # PDF 导出工具
└── stores/
    └── resumeStore.js               # 状态管理
```

**优势**:

- ✅ 组件职责清晰，易于理解
- ✅ 编辑区和预览区独立，可复用
- ✅ 新增岗位选择和博客导入功能
- ✅ 文件命名规范统一

### 4. blogParser.js

**位置**: `/src/utils/blogParser.js`  
**职责**: 博客数据抓取和解析  
**代码行数**: ~250 行

**主要功能**:

- 📝 解析 Markdown 格式简历
- 🔗 从 URL 获取博客内容
- 📂 从本地文件读取
- 🔄 数据合并和验证
- 📋 提供 Markdown 模板

**核心函数**:

```javascript
// 解析 Markdown 简历
parseMarkdownResume(markdownContent)

// 从 URL 获取并解析
fetchAndParseBlog(url)

// 从本地文件解析
parseLocalMarkdownFile(file)

// 合并简历数据
mergeResumeData(current, imported, options)

// 验证数据完整性
validateResumeData(resumeData)
```

**Markdown 格式示例**:

```markdown
---
name: 张三
title: 前端工程师
email: zhangsan@example.com
experience:
  - company: 某公司
    position: 高级工程师
    startDate: 2020-01
    endDate: 至今
---

# 关于我

这是个人简介...
```

## 🔧 文件重命名

### 重命名操作

| 原文件名       | 新文件名         | 原因                     |
| -------------- | ---------------- | ------------------------ |
| `resume.js`    | `resumeStore.js` | 明确表示这是 Pinia Store |
| `pdfExport.js` | `pdfExporter.js` | 统一命名规范（动词形式） |

### 路径变更

**路由配置**:

```javascript
// 旧路径
import ResumeGenerator from '../pages/ResumeGenerator.vue'

// 新路径
import ResumeGenerator from '../components/ResumeGenerator.vue'
```

**所有导入更新**:

```javascript
// 旧导入
import { useResumeStore } from '@/stores/resume'
import { exportResumePDF } from '@/utils/pdfExport'

// 新导入
import { useResumeStore } from '@/stores/resumeStore'
import { exportResumePDF } from '@/utils/pdfExporter'
```

## 🎨 组件通信架构

### 数据流

```
用户输入
  ↓
ResumeEditor (编辑区)
  ↓
Pinia Store (resumeStore)
  ↓
ResumePreview (预览区)
  ↓
PDF 导出 (pdfExporter)
```

### Store 依赖

所有组件都通过 Pinia Store 共享状态：

```javascript
// 在任何组件中
import { useResumeStore } from '@/stores/resumeStore'
const resumeStore = useResumeStore()

// 读取数据
const { resumeData } = storeToRefs(resumeStore)

// 调用方法
resumeStore.addExperience()
```

### 2. 博客数据导入

**支持的格式**:

- ✅ Markdown (.md)
- ✅ 带 YAML frontmatter
- ✅ 从 URL 获取
- ✅ 本地文件上传

**使用示例**:

```javascript
// 从 URL 导入
await fetchAndParseBlog('https://blog.com/resume.md')

// 从文件导入
await parseLocalMarkdownFile(file)

// 从 Markdown 字符串解析
const data = parseMarkdownResume(markdownContent)
```

**数据合并选项**:

```javascript
mergeResumeData(current, imported, {
  overwriteBasicInfo: true, // 覆盖基本信息
  appendExperience: false, // 追加工作经历
  appendEducation: false, // 追加教育背景
  overwriteSkills: true, // 覆盖技能列表
})
```

## 📝 最佳实践

### 组件开发

1. **保持组件小而专注**
   - 单一职责原则
   - 200-400 行为佳
   - 易于理解和维护

2. **使用 Pinia 共享状态**
   - 避免 props drilling
   - 集中管理状态
   - 易于调试

3. **提取可复用组件**
   - JobSelector 就是好例子
   - 其他表单也能用
   - DRY 原则

### 文件组织

1. **按功能分组**
   - 相关组件放在一起
   - 工具函数独立文件
   - Store 集中管理

2. **命名规范**
   - 组件用大驼峰
   - 工具函数用小驼峰
   - 文件名清晰明确

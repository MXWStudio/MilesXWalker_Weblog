## 🎯 开发背景

### 用户需求

用户反馈："我刷新浏览器后，数据就没有了，我需要在云端储存"

### 问题分析

- 用户的简历数据原本只存储在浏览器的localStorage中
- 如果清除浏览器缓存或更换设备，数据会丢失
- 需要一个可靠的云端存储方案来解决数据持久化问题

## 🏗️ 技术架构

### 数据流程

```
用户编辑简历
    ↓
本地localStorage自动保存
    ↓
用户点击"保存到云端"
    ↓
resumeStore.saveToCloud()
    ↓
resumeCloudService.saveResume()
    ↓
转换为JSON + 添加元数据
    ↓
上传到七牛云
    ↓
返回结果 + 更新状态
```

### 存储结构

```
七牛云存储空间
└── resumes/
    └── user_[唯一ID]/
        └── default.json
            ├── version: "1.0"
            ├── savedAt: "2025-10-11T12:00:00Z"
            ├── userId: "user_xxx"
            ├── data: { 完整简历数据 }
            └── metadata: { 浏览器信息等 }
```

### 用户识别机制

```javascript
用户ID = user_[设备指纹]_[时间戳]_[随机字符串]
```

- 首次访问自动生成
- 存储在localStorage
- 跨会话持久化
- 更换设备会生成新ID

## 🔐 安全特性

1. **数据隔离** - 每个用户有独立的存储路径
2. **访问控制** - 使用七牛云的访问控制机制
3. **数据加密** - HTTPS传输，数据安全可靠
4. **用户识别** - 唯一用户ID，防止数据混淆

## 📊 性能优化

1. **防抖保存** - 避免频繁上传，3秒内多次修改只保存一次
2. **断点续传** - 七牛云支持大文件断点续传
3. **并发控制** - 禁用按钮防止重复操作
4. **本地优先** - 本地localStorage快速加载，云端作为备份

## 🎯 使用场景

### 场景1：日常使用

```
编辑简历 → 本地自动保存 → 手动云端保存 → 数据双重备份
```

### 场景2：换设备

```
设备A保存 → 设备B加载 → 继续编辑 → 再次保存
```

### 场景3：数据恢复

```
清除缓存 → 数据丢失 → 从云端加载 → 数据恢复
```

### 场景4：数据备份

```
编辑简历 → 云端保存 → 导出JSON → 三重备份
```

### 局限性

1. **单一简历** - 当前只支持保存一份默认简历
2. **手动同步** - 需要用户手动点击保存按钮
3. **设备绑定** - 用户ID绑定设备，换设备需要重新加载
4. **版本控制** - 只保存最新版本，不支持历史版本

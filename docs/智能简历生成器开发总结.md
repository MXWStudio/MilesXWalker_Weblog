- 扫描About页面提取基本信息

#### 2. 岗位匹配分析器 (`useJobMatcher.js`)

**功能：**

- 分析用户能力与岗位要求的匹配度
- 识别符合要求的技能
- 识别缺失的技能
- 提供学习路径规划
- 给出简历优化建议

**分析维度：**

1. **匹配度评分** (0-100分)
   - high: 80-100分
   - medium: 60-79分
   - low: 0-59分

2. **符合的技能**
   - 技能名称
   - 用户熟练度
   - 岗位要求
   - 状态（符合/超出）

3. **优势分析**
   - 相比其他候选人的独特优势
   - 2-5个核心竞争力

4. **缺失技能**
   - 按重要性分类：
     - critical: 必须掌握
     - important: 建议掌握
     - nice-to-have: 加分项
   - 预计学习时间
   - 推荐学习资源

5. **学习路径**
   - immediate: 立即行动（本周）
   - shortTerm: 短期目标（1-3个月）
   - longTerm: 长期规划（3-6个月）

6. **简历优化建议**
   - 按优先级排序
   - 针对具体简历部分
   - 可操作的改进建议

**AI Prompt设计：**

```
你是一位专业的职业匹配分析专家和HR顾问。

分析用户与目标岗位的匹配程度，提供详细的匹配报告。

目标岗位：[岗位名称]
用户能力画像：[技能、经验、项目等]

输出JSON格式，包含：
- matchScore: 匹配度评分
- matchingSkills: 符合的技能列表
- advantages: 优势分析
- missingSkills: 缺失技能（按重要性分类）
- learningPath: 学习路径规划
- resumeOptimization: 简历优化建议
- overallAssessment: 整体评价
```

## 🔧 技术实现细节

### 1. 数据流管理

```
用户操作
  ↓
智能扫描器 → scannedProfile (ref)
  ↓
AI分析 → aiAnalysis (嵌入profile)
  ↓
填充Store → resumeStore.resumeData
  ↓
AI优化 + 岗位匹配
  ↓
matchAnalysis (ref) → JobMatchAnalysis组件
  ↓
应用优化 → 更新resumeData
  ↓
简历预览 → ResumePreview组件
```

### 2. 状态管理

**Local State (组件内部):**

- `scanning`: 扫描状态
- `scannedProfile`: 扫描结果
- `matchAnalysis`: 匹配分析结果
- `showMatchAnalysis`: 是否显示分析
- `showEditor`: 编辑器显示状态

**Global State (Pinia Store):**

- `resumeData`: 简历数据
- `lastSaved`: 最后保存时间
- `completionPercentage`: 完成度

### 3. API调用优化

**并行调用：**

```javascript
// 优化后的流程
async handleAIOptimize() {
  // 1. 先执行简历优化
  const aiResult = await generateSmartResume(...)

  // 2. 同时启动岗位匹配分析（不阻塞主流程）
  try {
    const matchResult = await analyzeJobMatch(...)
    showMatchAnalysis.value = true
  } catch (error) {
    // 失败不影响主流程
    console.warn('匹配分析失败', error)
  }
}
```

**错误处理：**

```javascript
try {
  // 主要功能
  const profile = await intelligentScan()
} catch (error) {
  // 友好的错误提示
  if (error.message.includes('API')) {
    alert('请配置API Key')
  } else {
    alert('扫描失败: ' + error.message)
  }
}
```

## 📊 性能优化

1. **懒加载组件**
   - JobMatchAnalysis只在需要时渲染
   - 编辑器可折叠减少渲染

2. **数据缓存**
   - scannedProfile缓存扫描结果
   - 避免重复扫描和分析

3. **异步加载**
   - AI分析不阻塞主流程
   - 匹配分析在后台进行

## 🐛 已知问题和限制

1. **AI分析需要API Key**
   - 解决方案：提供fallback默认分析
   - 或使用本地Ollama模型

2. **扫描依赖固定数据结构**
   - 当前针对MilesXWalker网站定制
   - 需要适配其他网站结构

3. **匹配分析准确度**
   - 依赖AI模型质量
   - 建议作为参考而非绝对标准
